# Audit du dossier de la séance 02

Date : 28 septembre 2026.

Cet audit décrit l’état initial. Les corrections appliquées ensuite et leurs contrôles sont recensés dans `docs/CONTROLE-DU-PACK.md`, section « Vérification après correction de l’audit ».

## Conclusion

Le projet compile et reproduit exactement la version distribuée. Le contrôle automatique intégré réussit. Aucun blocage de compilation n’a été constaté. Des corrections de navigation, de documentation et de couverture des contrôles sont recommandées avant de considérer la vérification comme complète.

Les deux fichiers prioritaires n’étant pas nommés dans la demande initiale, cet audit commence par `README.md` et `PROMPT-MAITRE-PRODUCTION-DEPLOIEMENT.md`. Il couvre ensuite les sources web, les scripts, le workflow et le contenu des deux Word candidats. Le guide source de 24 pages n’a pas fait l’objet d’une comparaison détaillée.

## 1. README.md

Le README décrit correctement les 16 écrans, les deux Word, les quatre dossiers pédagogiques et les résultats attendus. La distinction entre trois livrables définis aujourd’hui et leur réalisation ultérieure est claire. L’adresse publique est présentée comme une cible, sans prétendre que la publication est terminée.

### À corriger : les commandes npm sous PowerShell

- Références : `README.md:28`, `README.md:37`, `docs/PUBLICATION-GITHUB-PAGES.md:26`.
- Constat reproduit : `npm --version` échoue ici parce que PowerShell refuse l’exécution de `npm.ps1`.
- Conséquence : les commandes copiées par le formateur dans ce terminal peuvent bloquer dès l’installation.
- Correction proposée : ajouter une note Windows indiquant d’utiliser `npm.cmd ci`, `npm.cmd run build`, `npm.cmd run check` et `npm.cmd run dev` dans ce cas. Aucune modification de la politique PowerShell n’est nécessaire.

### À préciser : ZIP fourni et téléchargement depuis GitHub

- Références : `README.md:9`, `README.md:15`, `.gitignore:2`, `scripts/serve-dist.mjs:14`.
- Le démarrage immédiat fonctionne pour ce dossier, qui contient `dist`.
- `dist/` est exclu du suivi Git. Un futur clone ou ZIP des sources GitHub ne contiendra donc pas cette version compilée si cette exclusion est respectée.
- Conséquence : le lanceur ne pourra pas démarrer avant une première compilation dans cette copie des sources.
- Correction proposée : documenter séparément le démarrage du pack fourni et celui des sources téléchargées depuis GitHub. Pour ces dernières, indiquer l’installation puis la compilation, ou fournir une archive de distribution contenant `dist`.

## 3. Constats dans le reste du projet

### Priorité moyenne : le lien « Aller au contenu » quitte les ressources

- Références : `index.html:11`, `src/main.js:103`, `src/main.js:202`.
- Le lien d’évitement utilise `#content`. La page Ressources n’est reconnue que lorsque l’ancre vaut exactement `#ressources`.
- En activant ce lien depuis les ressources, l’ancre devient `#content`. Le gestionnaire `hashchange` appelle alors `render()`, qui affiche une diapositive à la place des ressources.
- Correction proposée : gérer ce lien en déplaçant le focus vers le contenu sans changer l’ancre de navigation.
- Niveau de preuve : défaut identifié par lecture du code ; reproduction dans un navigateur à effectuer.

### Priorité moyenne : le contrôle des fichiers privés est incomplet

- Référence : `scripts/check-pack.mjs:31`.
- Le script rejette certains noms exacts, notamment `.env`, `prive` et `reponses`, uniquement dans `dist`.
- Il ne rejette pas par cette règle les variantes telles que `.env.production`, une fiche nominative rangée ailleurs, ni un fichier privé ajouté aux sources du futur dépôt.
- Aucun fichier de ce type n’a été constaté dans les six fichiers de `dist`. Il s’agit d’une limite de prévention, pas d’une fuite constatée.
- Correction proposée : étendre les motifs détectés et vérifier la liste réelle des fichiers destinés au commit avant publication. Conserver une lecture humaine des documents distribués.

### Priorité faible : le contrôle pédagogique ne vérifie pas les cinq modèles

- Références : `scripts/check-pack.mjs:6`, `scripts/check-pack.mjs:20`, `modeles-candidat/`.
- Le script vérifie que quatre noms de dossiers figurent dans le JavaScript, mais ne vérifie pas l’existence des cinq fichiers Markdown annoncés.
- Les cinq modèles sont présents dans ce dossier. Une suppression ultérieure pourrait toutefois passer ce contrôle.
- Correction proposée : ajouter ces cinq chemins à la liste des fichiers requis.

### Priorité faible : préciser le contrôle dans le modèle des livrables

- Référence : `modeles-candidat/03-livrables/liste-premiers-livrables.md`.
- Le guide candidat demande un « premier contrôle ». Le modèle propose un « critère de réussite », sans champ distinct décrivant la vérification à réaliser.
- Correction proposée : ajouter « Premier contrôle à réaliser » à chaque livrable, en conservant le critère de réussite.
